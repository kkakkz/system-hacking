## 레지스터
- CPU가 실제로 담아두고 연산하는 그릇.
다음에 배울 스택(rsp)과 컨트롤플로우(rip)를 이해하려면 "레지스터가 뭐고 어떻게 값을 넣고 빼는지"가 먼저 확실해야한다.

## 왜 배워야하는가
- 익스플로잇의 최종 목표는 결국 **"CPU가 다음에 실행할 명령어 주소(rip)를 내가 원하는 값으로 바꾸는 것"**이다.
그런데 rip 자체를 직접 `mov`로 건드릴 수는 없고, 스택 조작이나 다른 레지스터 값 조작을 통해 간접적으로 바꿔야 한다.
그래서, "레지스터에 값이 어떻게 들어가고, 어떻게 잘리고, 어떻게 부분적으로 접근되는지"를 지금 확실히 알아둬야, 나중에 레지스터 버그를 이해할 수 있다.

## 개념
- 1. 레지스터 = CPU안에 초고속 임시 저장소 `[보조]`

- 2. 레지스터 크기 계보 : al->ax->eax->rax `[핵심]`
  - 8비트 : `al` (a register, low)
  - 16비트 : `ax` (`ah`+`al` = 상위 8비트 + 하위 8비트)
  - 32비트 : `eax` (extended ax)
  - 64비트 : `rax` (real/registered extended ax)

  즉 `rax`의 하위 32비트가 `eax`, `eax`의 하위 16비트가 `ax`, `ax`의 하위8비트가 `al`이다.
  **왜 핵심이냐** : BOF(버퍼 오버플로우)에서 몇 바이트를 덮었는지, leak한 주소가 몇 바이트짜리인지 계싼할 때 이 크기 개념이 그대로 쓰임.

- 3. `mov` 명령어 - 값 넣기 `[핵심]`
```text
mov rax, 0x539
```
"rax에 0x539를 넣어라"는 뜻. 여기서 `0x539`처럼 코드에 직접 박혀있는 값을 *immediate value(즉치값)*라고 부른다.
```text
mov rbx, rax
```
rax의 값을 rbx로 "복사"하는 것 - mov라고 부르지만 rax는 파괴되지 않고 그대로 남는다. destination가 왼쪽, source가 오른쪽이다.

- 4. 32비트에 쓰면 상위 32비트가 0으로 날아간다 (Zero-extension) `[핵심]`
```text
mov eax, -1
```
이걸 실행하면 `eax`(하위32비트)는 `0xffffffff`가 되지만, `rax`전체를 보면 사우이 32비트가 **자동으로 0으로 초기화**돼서 `rax`는 `0x00000000ffffffff` (음수 -1이 아니라 그냥 큰 양수)가 되어 버린다.
**왜 핵심이냐**: 32비트 연산 결과를 64비트 컨텍스트에서 쓸 때, 또는 익스플로잇 페이로드에서 레지스터 값을 조작할 때 이 zero-extension을 안 알고 있으면 값이 왜 깨지는지 못 찾는다.

- 5. `movsx` - 부호 확장 이동 `[보조]`
```text
mov eax, -1     ; eax = 0xffffffff (rax 상위 32비트는 0으로 리셋됨)
movsx rax, eax  ; eax의 부호를 보고 그걸 살려서 rax 전체에 확장
```
`movsx` (move with sign extend)는 값이 음수인지 보고, 음수면 상위 비트를 전부 1로 채워서 2의 보수값을 그대로 보존한다. 그래서 결과적으로 `rax`가 진짜 64비트 `-1` (`0xffffffffffffffff`)이 된다.

- 6. 기타 연산 명령어들 `[보조]`
`add`, `sub` (더하기/빼기), `inc`/`dec` (1증가/감소), `or`, `xor`, `shl`/`shr`(시프트), `xchg`(두 레지스터 값 스왑) - 지금은 "이런게 있다" 정도로 넘어가고, 실제로 자주 쓰면서 자연스럽게 익혀질 것"

- 7. 특수한 레지스터 : rip, rsp `[핵심 - 다음 예고]`
  - rip : 다음에 실행할 명령어의 주소. 익스플로잇의 최종 타켓.
  - rsp : 스택이라는 특수 메모리 영역의 주소를 가리킴.

## 시스템 해킹 연결점
- 이 레지스터 크기/zero-extension 개념은 나중에 Buffer Overflow (스택에 덮어쓸 때 몇 바이트를 덮어야 rip까지 도달하는 계산할 때), 레지스터 기반 shellcode 작성 ( syscall 넘길 때 rax/rdi/rsi/rdx 크기를 정확히 맞춰야 할 )
