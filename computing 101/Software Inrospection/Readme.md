## Software Introspection 
점점 더 큰 프로그램을 작성하다보면, 너도 특정 기능을 구현하면서 실수를 저지를 수 있고, 그 결과 프로그램에 버그가 생길 수 있다.
이런 일이 생기면, 뭐가 잘못됐는지 파악하고 고칠 수 있는 믿을만한 도구 상자가 필여하다. 물론, 정확히 똑같은 긱버들을 써서 너가 작성하지 않은 코드에 뭐가 잘못됐는지 파악하고, 원하는 대로 고치거나, 익스플로잇할 수 있다.
이 모듈은 소프트웨어를 들여다보고(introspect), 디버깅하고, 이해하는 여러 방법들을 소개한다.

## 왜 배워야 하는가
지문이 아주 솔직하게 짚어주는 포인트 : **버그를 찾는 도구와 취약점을 찾는(익스플로잇하는) 도구는 완전히 동일하다**. 개발자가 "내 코드가 왜 크래시 나지?"를 알아내려고 쓰는 디버거가, 공격자 입장에서는 "이 프로그램이 왜 크래시 나는지, 그걸 어떻게 악용할지"를 알아내는 도구가 된다.
즉, 이 모듈이 사실상 **네가 목표로 하는 시스템해킹의 실전 도구를 배우는 첫 단계**이다.
