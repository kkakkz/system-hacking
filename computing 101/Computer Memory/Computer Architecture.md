## 1. 모든 길은 CPU로 통한다
- Python이든, Rust든, Javascript든, 컴파일러나 인터프리터를 거치면 결국 전부 **CPU가 실행하는 이진 인코딩된 명령어**로 변환된다. 어떤 고급언어를 쓰든 최종 종착지는 같다.

## 2. 논리 게이트
- CPU내부를 극한까지 파고들면 결국 AND, OR, XOR, NOT 같은 논리 게이트들의 집합이다.
  - AND : 두 입력이 모두 참일 떄만 참
  - OR : 둘 중 하나라도 참이면 참
  - XOR : 둘 중 정확히 하나만 참일 떄 참
  - NOT : 입력을 반전

이 게이트들을 조합해서 덧셈기(adder), 멀티플렉서(memory 읽기/쓰기에 쓰임) 같은 더 복잡한 회로를 만들 수 있고, 이게 쌓이고 쌓여서 결국 "컴퓨터"라는 마법 같은 결과물이 나온다는 얘기이다.

## 3. CPU의 내부 구성 요소
- Control Unit (제어 유닛) : 어떤 명령어를 실행할지 디코딩하고 지시를 내림
- ALU (산술 논리유닛) : 실제 덧셈/뺄셈 등 연산이 일어나는 곳
- Register : CPU안에 있는 작고 빠른 저장 공간

## 4. 메모리 계층 구조
```text
느림/큼                                          빠름/작음
인터넷  →  디스크(Disk)  →  메모리(RAM)  →  캐시(Cache)  →  레지스터
```
- 속도-크기 트레이드오프 : 작을수록 빠르고, 클수록 느리다. 레지스터는 극도로 빠르지만 개수가 8-40개 뿐이고 각각 몇 바이트밖에 못담는다. 반면 디스크는 엄청 크지만 접근이 느리다.
- CPU는 실제로 **캐시와 레지스터에 있는 것만 직접 연산**한다. 메모리, 디스크는 필요할 때마다 이 빠른 계층으로 load되어야 CPU가 쓸 수 있다.
**왜 핵심이냐?** : 이 계층 구조를 알아야 "왜 메모리에 있는값을 레지스터로 먼저 옮겨야 하는지(`mov reg, [address]`)", 그리고 나중에 캐시 사이드채널 공격같은 고급 주제를 이애할 기반이 생긴다. "메모리는 레지스터보다 훨씬 크지만 느리다" 라는 감각 자체가 Computer Memory 이해에 도움이 된다.

## 5. 폰 노이만 구조 (Von Neumann Architecture)
```
"CPU는 캐시/레지스터에서 작업할 때, 대부분 데이터와 코드를 구분하지 않는다"
```
- 코드와 데이터가 메모리상에서 근본적으로 구분되지 않는다는 이 특성이, 나중에 배울 **버퍼 오버플로우가 왜 가능한지, shellcode 인젝션이 왜 통하는지**의 근본 원리이다. "데이터인줄만 알았던 영역에 CPU가 명령어라고 착각하고 실행해 버리는 것"이 바로 메모리 기반 익스플로잇의 본질이다.
