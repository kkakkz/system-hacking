## Dealing with Data (Hex)
- 이 내용은 앞서 배운 "니블 = 4비트 = 16진수 한 자리"라는 개념을 **실전 도구(`xxd`)로 손에 익히는**파트이다.
새로운 이론보다는 "16진수를 실제로 어떻게 다루고 변환하는지" 실무 감각에 가깝다

## 왜 배워야 하는가
- 지금까지 강의에서 "니블 = 4비트 = 16진수 한 자리"라고 배웠는데, 이번엔 그걸 **바이트 단위로 확장**해서 "1바이트 = 16진수 두 자리"라는 걸 명확히 하고, 실제로 파일이나 메모리 덤프를 16진수로 어떻게 다루는지(`xxd`명령어)보여준다.
이건 나중에 **GDB로 메모리를 hex dump로 확인**하거나, 바이너리 파일을 hex editor로 열어서 패치할 때 매일 쓰게될 기본기이다.

## 바이트 = 니블 2개 = 16진수 2자리
```
1바이트(8비트) = 니블(4비트) + 니블(4비트) = 16진수 2자리
예 : 0110 1000 -> 니블 0110(=6) + 니블 1000(=8) -> "68"
```
여러 바이트를 16진수로 나타낼 땐 그냥 **바이트 하나씩 개별적으로 2자리 16진수로 바꿔서 이어붙이면 된다** - 이게 우리가 GDB나 hex editor에서 보는 `41 42 43 ... `같은 표기의 정체이다.

## hex는 "보는 방식"일 뿐, 데이터는 여전히 2진수이다.
- 파일이나 메모리 안의 실제 데이터는 언제나 순수 2진수(비트)이다. hex editor로 파일을 열어도 **파일 자체가 바뀌는게 아니라, 그 비트들을 사람이 읽기 편하게 16진수 "렌즈"로 보여주는 것 뿐**이다.
hex는 표현 방식이지 실제 저장 형식이 아니다.

## 실전 도구 : `xxd`
```bash
xxd - ps 파일명      # 파일을 16진수로 인코딩해서 출력
xxd -ps -r           # 16진수를 다시 원본 바이너리로 디코딩
```
바이너리 데이터(이미지 파일 등)를 사람이 종이에 옮겨적거나 텍스트로 전송하기 편하게 16진수로 바꾸는 실용적인 이유이다. 0~9, A~F만 쓰니까 타이밍하기도, 읽기도 훨씬 쉽다.

>니블 개념(4비트=16진수 한 자리)이 이번엔 **바이트 단위 실무**로 확장됐다:6(=`0110`)과 8(=`1000`)을 붙이면 `68`이라는 실제 바이트 값이 되는걸 손으로 확인한 셈이다.
