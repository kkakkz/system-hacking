## Data 모듈 시작
**바이트(Byte)**는 8비트이다. 그 절반인 **니블(nibble,4비트)**도 존재한다. 이 모듈에선 비트단위부터 차근차근 숫자를 파고든다.
비트더미가 어떻게 2진수, 16진수, 10진수에서 양수나 음수라는 **의미**를 갖게 되는지 다룬다. 
이걸 이해하는것은 CPU가 비트를 어떻게 더 의미 있는 것으로 처리하는지 알기 위한 핵심이다.

## 왜 배워야하는가
지금까지 `mov eax, -1`을 실행하면 `rax`가 `0xffffffff`가 된다든가, 리틀엔디안으로 바이트가 뒤집힌다든가 하는걸 "일단 그렇다더라"로 넘어갔다. 
이 모듈은 그 **"왜"**를 채워준다. - 컴퓨터가 음수를 어떻게 표현하는지(2의보수), 16진수가 왜 사람이 비트를 다루기 편한 표기법인지 알아야, 나중에 **정수 오버플로우 취약점**, **부호관련 버그** 같은걸
"그냥 외운 규칙"이 아니라 "왜 그런 취약점이 생기는지" 원리로 이해할 수 있다.

## 핵심 개념
- **니블(nibble)** : 4비트 = 16진수 자리 하나.
- **2의 보수(2's complement)** :"0xFF + 1 = 0x00 (8비트)", "0xffffffffffffffff = -1" 같은 규칙으로 정리해뒀던 개념이 여기서 원리부터 설명됨.
- **비트 -> 니블 -> 바이트 -> 워드 -> 레지스터** 로 이어지는 단위 감각이, 결국 `al/ax/eax/rax` 크기 계보 이해의 근본 바탕이다.
