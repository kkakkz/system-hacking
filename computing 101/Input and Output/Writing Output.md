## `write` syscall 로 텍스트 출력하기

당연하게도, 프로그램은 시스템 콜을 호출함으로써 화면에 텍스트를 쓴다. 구체적으로는, 이게 `write`시스템 콜이고, syscall 번호는 1이다.
근데 `write` 시스템 콜은 파라미터를 통해 **어떤 데이터를, 어디에 쓸지**도 명시해줘야 한다.


모든 프로세스는 시작할 때 기본적으로 3개의 FD(파일 디스크립터)를 가진다 : 
 - FD 0: 표준 입력(Standard Input) - 프로세스가 입력을 받는 통로이다. 예를 들어, 쉘은 표준 입력을 통해 내가 입력하는 명령어를 읽는다.
 - FD 1: 표준 출력(Standard Output) - 프로세스가 일반 데이터를 출력하는 통로이다. 예를 들어 이전 챌린지들에서 플래그가 출력됐을 때나, `ls` 같은 유틸리티의 출력이 나올 대 쓰이는 통로이다.
 - FD 2: 표준 에러(Standard Error) - 프로세스가 에러 세부사항을 출력하는 통로이다. 예를 들어, 명령어를 잘못 입력하면 쉘이 "그런 명령어는 없다"는 걸 표준 에러로 출력한다.

바로 이게 내 `write` 시스템 콜에서 **데이터를 어디에 쓸지 지정하는 방법**이다. `eixt` 시스템 콜의 첫 번째(이자 유일한) 파라미터가 종료코드 (`mov rdi, 42`) 였다면 `write`의 첫 번째 파라미터는 **파일 디스크립터**이다.
표준 출력에 쓰고 싶으면 `rdi`를 1로 설정하면 된다. 표준 에러를 쓰고 싶으면 `rdi`를 2로 설정하면된다.

## 핵심 개념

### 파일 디스크립터(FD)
```
0 = stdin  (표준 입력)
1 = stdout (표준 출력)
2 = stderr (표준 에러)
```
`write`의 1번째 인자 (`rdi`)로 "어디에 쓸지"를 지정한다.

### `write` syscall의 3개 인자
```assembly
mov rdi, 1              ; 1번째 인자: fd (1 = stdout)
mov rsi, memory_address  ; 2번째 인자: 쓸 데이터의 시작 주소
mov rdx, length           ; 3번째 인자: 몇 바이트 쓸지
mov rax, 1               ; syscall 번호: write = 1
syscall
```

### `rdi` vs `rdx` 혼동 주의
```
rdi = 1번째 인자 (initial)
rdx = 3번째 인자 (extra)
```

### argv에서 문자열 주소 가져오기
```assembly
mov rsi, [rsp+16]  ; 역참조의 첫 단계 - 포인터만 가져오면 됨
```
`rsi`가 필요로 하는건 **주소 자체** 이기 때문에 `[rsp+16]`을 한 번만 읽으면 끝이다.
